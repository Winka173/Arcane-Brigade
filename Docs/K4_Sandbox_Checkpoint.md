## Entry and discovery

- Run frontend: Records / Collection → THỬ VŨ KHÍ / SANDBOX. Uses the existing skin, typography, built-in renderer and 1280×720 root coordinates; no font or UI redesign.
- Eligibility comes only from `PlayerProfile.SeenWeapons`, optionally unioned with the already-loaded saved roster's actual `WeaponId` values and the saved champion's default weapon. `SeenUnits` never implies possible weapon rolls. Unknown IDs are ignored, duplicates collapsed, empty discovery shows instructions rather than granting a weapon.
- Main owns the new `SeenWeapons` field, null-to-empty Version 1 migration, committed roster discovery in `RecordProgress` and champion discovery at `ArenaController.PersistBoundary`. Sandbox never writes discovery or invokes persistence.
- Tiers 1–3 are explicitly **PREVIEW — NOT OWNED**, even for discovered weapons. Base weapon, catalog tier damage multiplier and companion tier silhouette scaling are used. No relic, bond, passive, arena toy or connector bonuses; source companion base critical chance is retained. Cooldown windup/recovery clamps match ordinary combat preparation.
- Settings includes the existing-style reduced-motion button backed by `PlayerProfile.ReducedMotion`; failed `SaveProfile()` rolls the bool back. Sandbox snapshots this preference at open and sets `UnitVisual.ReducedMotion` before binding every local visual. Tier/reset preserve it; shared idle suppression does not replace priority attack/hit poses or change simulation cadence.

## Isolation and presentation

`WeaponSandbox` copies catalog settings, unit definitions, weapon definitions and mutable tag arrays into transient local ownership. Sprite/prefab assets are read-only shared presentation resources. Each reset builds fresh working clones and a fresh `CombatSimulation` seeded with `PreviewSeed = 45016`; no run/global RNG is used.

An inert hidden champion anchors one stationary companion. The ordinary simulation boss slot hosts a non-boss, immortal, non-attacking dummy without special attack rules or editor-only spawning APIs. Stationary/moving targets are scripted presets (vertical sine motion); dummy position is restored each tick, so pushes are transient rather than moving it permanently out of range. No reward, kill or loot production is possible in the ordinary preview. Local simulation diagnostics are discarded, never settled into a run.

Auto attacks, signature cadence, projectiles and impacts use `CombatSimulation.Step`, `UnitVisual.Bind/Display`, `ProjectileVisual`, `ArcadeEffects.Play/Advance` and presentation-configured `CheckpointAudio.Play`. A disabled orthographic camera manually renders its own transient scene to a local RenderTexture: desktop 2560×1280 / MSAA4 for sharp 4K previews, mobile 880×440 / MSAA2 selected by `Application.isMobilePlatform` and gated on K7 device acceptance. The IMGUI design rectangle stays 760×380 and camera aspect stays 2:1. All local renderers are forced off outside the synchronous camera render and isolated to layer 31; existing cameras and masks are not modified. No extra listener is created if one already exists. Close/reset disable the transient world, stop its audio, unload the scene and release texture/clones; play-mode Unity object destruction and asynchronous scene unloading finish at the normal frame boundaries.

Controls: left/right arrows or LB/RB select weapon; 1/2/3 select tier, controller A cycles tier; T/controller X changes target; R/controller Y resets; Escape/controller B/top Back returns to the previous menu page and scroll. All actions have touch-sized IMGUI buttons. No attack/skill input. Lost focus or application pause stops preview stepping.

## Integration hooks (main/runner)

- `RunMenu.OpenWeaponSandbox()` opens from its already-loaded catalog/profile/saved snapshot, without reload/save calls. `ShowPage(RunMenu.Page.WeaponSandbox)` routes here too.
- `RunMenu.OpenWeaponSandboxForDiagnostics(RunCatalog definition, PlayerProfile readOnlyProfile, RunSnapshot readOnlySaved = null, string weaponId = null, int tier = 1, bool moving = false)` opens directly for native capture. Call before `Start` on a fresh menu component to bypass normal frontend storage initialization. Supply a synthetic profile whose `SeenWeapons` contains desired test IDs; this method never grants them. Use an isolated frontend/capture scene, not a live arena. No `RunPaths` changes are needed.
- `RunMenu.Sandbox` / `GetSandbox()` expose the component (null before first open); `CloseWeaponSandbox()` disposes it and restores the previous page/scroll. Native capture can also use `GetComponent<WeaponSandbox>()` after opening.
- `WeaponSandbox.Open(...)` accepts the same state and selection parameters plus `bool createPresentation = true`. Checks pass false to validate model isolation without native renderer/audio initialization.
- `ResetPreview()`, `SelectWeapon(string)` (false for unavailable IDs), `CycleWeapon(int)`, `SetTier(int)`, `SetMovingTarget(bool)`, `AdvancePreview(float)` (valid steps ≤0.1s), `RenderPreview()` and idempotent `Dispose()` support deterministic runners. Do not manually advance alongside automatic `FixedUpdate` during a live capture.
- Diagnostics: `IsOpen`, `Tier`, `MovingTarget`, `WeaponCount`, `SelectedWeaponId`, `Simulation`, `Attacker`, `PreviewTexture`, `FireEvents`, `HitEvents`, `SignatureEvents`, `RuntimeAssetCount`, `TemplateAssetCount`. `Simulation`/`Attacker` belong only to the preview, never the persisted run.
- Capture access: `PreviewCamera`, `PreviewTexture`, `GetUnitVisual(int unitId)` (null without presentation or for unknown IDs). Pass `Attacker.Id` to inspect its live `UnitVisual`. `GetPreviewDescriptor(bool mobile)` exposes the allocation settings without allocating: desktop 2560×1280 / MSAA4, mobile 880×440 / MSAA2, both ARGB32. The camera explicitly uses 2:1 aspect and opaque clear alpha; IMGUI preserves aspect and disables alpha blending. Main verifies platform MSAA support, resolved alpha and 4K framing; mobile remains a K7 gate.
- Native playback is unchanged: `bool SelectWeapon(string id)` returns true and resets on an eligible ID, false without resetting for unavailable IDs; `void SetTier(int tier)` clamps to 1–3 and resets when open; `void SetMovingTarget(bool moving)` updates the `bool MovingTarget` getter and resets when open. These resets recreate presentation and resume normal `FixedUpdate` auto attacks; they do not pause or switch to fixture-only playback. Reacquire camera, texture and unit visuals after any reset.
- `ReducedMotion` exposes the local preference; `SetReducedMotion(bool)` updates existing preview visuals only, without profile writes, combat reset or RNG changes.
- Main integrates `ArcaneBrigade.Editor.K4SandboxChecks.Run()` into `K4FinalBuilder`. It does not build or launch Unity. The editor menu is **Arcane Brigade/K4/Check isolated weapon sandbox**; successful execution writes `PreviewExports/K4/Sandbox_Checks.txt` and logs `ARCANE_K4_SANDBOX_CHECKS_PASSED`.
