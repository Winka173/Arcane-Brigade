## Main integration contract

- Main's `CheckpointCatalog.EnableArenaToys` gates props; `EnableBossArenaPhase` independently gates the layout phase (which needs props enabled to have a layout). Both default false; main enables them through `RunCatalog.SignatureRevision`. Propagate the run seed to `catalog.Seed`. No save-schema change is required.
- After `CombatSimulation.Start` has spawned Champion/companions/Boss and entered Combat, call `ResetArenaToys(waveNumber)` with the actual run wave (1-based). The signature is `ResetArenaToys(int wave = 1)`, so `ResetArenaToys()` is valid but means wave 1. Layout uses only `catalog.Seed`, wave and a dedicated RNG salt, never combat/shop/loot RNG. Repeated calls reset gameplay intentionally; do not call from rendering, camera entry, pause or Details.
- Call `ProcessArenaToys(deltaTime)` exactly once inside the accepted Combat step, after `ProcessSignatures` and before victory evaluation/removing dead units. It reads the already advanced `Elapsed`; it does not advance time. It detects the half-health boss phase itself, so `ProcessBoss` needs no extra branch. Existing boss bullet patterns remain unchanged.
- Call `ClearArenaToys()` on rest/run teardown and non-resumable wave boundaries. Reset at each new wave. Paused Step/impact calls reject work. State is combat-local, not a mid-wave save system.
- At eligible automatic allied **impact**, call `NotifyArenaToyHit(source, start, end, impactRadius, direction, cause)`. `source` must be a living Champion/Companion with matching `cause.SourceUnitId`, nonzero `RootId`, and `Depth == 0`. Use one cause per logical attack/projectile, retained from emission through travel; do not allocate a new root per collider/candidate callback. This API must never be called from player interaction/skill input, windup, Fire presentation, enemy attacks, status/echo/proc damage or prop payoffs.
- Convenience overloads: `NotifyArenaToyHit(CombatEvent impact)` accepts a positive enemy Hit event and resolves the allied source from its root cause; `NotifyArenaToyHit(Vector2 point, Vector2 direction, CombatCause cause)` resolves the source for a point footprint. `NotifyArenaToyHit(Vector2 point, CombatCause cause)` also exists, using a rightward cart fallback; prefer explicit impact direction. These are actual nearby-hit spillover (prop footprint 0.45), not projectile flight coverage. Dispatch only newly produced events, not the entire historical event list each tick. Root deduplication still protects repeated callbacks.
- For projectiles, pass the actual swept segment, truncated to the nearest blocking enemy hit, and the physical projectile radius (currently 0.055). Call even if no enemy was hit so spillover can charge a prop along flight. Props do not block or consume the projectile. Resolve the source via `SourceUnitId`. Main now stores `ProjectileState.Cause` from `attackCause` and retains it through all segments and enemy-hit callbacks; sibling projectiles from one logical attack share that root.
- For melee, pass the actual resolved contact/spillover footprint: `start == end == impactPosition` and the authored physical contact radius. Do not pass a whole attack-range disc or arbitrary target candidates, which would turn this into an omnidirectional skill. A swept blade may use its real contact segment. The API is capsule geometry, not a cone solver; main remains responsible for weapon cone/locked-target eligibility.
- Create one `ArenaToyVisual` component under the arena world hierarchy; call `Display(simulation, interpolationAlpha)` from `ArenaController.Render`. It owns native mesh/line resources, reads simulation only, clears on generation/simulation/count change, hides outside combat/pause, and preserves gameplay when absent. Keep its root world transform identity, matching the XY world used by `BossTelegraph`.
- Run `ArcaneBrigade.Editor.K4ArenaChecks.Run()` after flag integration. Its menu item runs checks only (no build). `ArenaToyTickFixture` is editor-only isolated timing: it deliberately does not run AI, contact attacks, wave completion or shared Step hooks. Include ordinary full combat regressions separately after main wires calls.

No new damage helper is needed: the partial uses existing private `ApplyDamage`, `SegmentCircle` and `ClampPosition`. Payoffs retain the triggering root with `SourceUnitId = 0`, effect ID and depth one; main's `RecordDamage(cause, actualHP)` automatically attributes effective damage to ARENA without double accounting. Shared damage callbacks must preserve this child cause, never replace it with a fresh root.

## Gameplay and safety

Wave one introduces only the stage bell; wave two and later offer both bell and cart when placement is safe. These are opportunities, not progression requirements: stage bell needs three unique eligible roots; toy cart needs two. Each prop deduplicates accepted roots across its entire wave (reset only at boundary). Secondary causes cannot charge anything. Per-prop root sets grow with finite wave impacts; there is no roster/event cap. No loot is generated by charging or moving props; ordinary logical enemy deaths continue through the shared single-death path. Each actual payoff calls the main ledger's `RecordActivation(toy.Cause)` once, not once per victim or cart sweep segment.

Both warn 1.2 seconds before activation, then cool down five seconds. Bell deals 14 physical damage in radius 2.4. Cart travels at most four units, slows quadratically over 0.8 seconds, sweeps with radius 0.55 plus enemy radius, and hits each enemy once per activation for 18. Cart remains where it stops and can charge again after cooldown. Boss damage is multiplied by 0.35 and capped at 8% authored max HP per payoff. Low-health enemies/bosses can still die normally; a full-health boss cannot be one-hit. All payoff hits carry depth-one `arena-stage-bell` / `arena-toy-cart` causes and cannot recursively trigger root-only procs.

Placement leaves 1.1 units from walls, Champion radius + two units clearance, other living unit clearance, three units between props, and 1.2 units from loot. Active boss telegraphs veto new placement. Bounded 96-attempt search omits unsafe props in crowded/tiny arenas; props have no colliders, block no movement/projectiles, and never reposition/harm allies. Cart endpoints retain 0.65 wall margin. Existing safe prop positions can later be crossed by units/loot without collision or harm.

One phase triggers on a living boss at <=50% authored max HP. Seeded destination rings preview for 1.2 seconds; pending charges/rolls are cancelled into cooldown. Positions are revalidated at completion: if Champion/loot/telegraph moved into a preview, that prop stays put rather than teleporting onto them. No reroll or repeated threshold phase. Boss death cancels a pending shift. This intentionally changes only prop opportunities, never boss bullet damage, Champion HP or ally formation. With no safe new space, a phase may have no physical relocation.
